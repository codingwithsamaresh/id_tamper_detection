# ID Document Tamper Detection (MIDV-2020 / MIDV-500)

A computer-vision pipeline that classifies identity-document images as **genuine** or **tampered**. OpenCV handles text-field localisation and forgery synthesis, and a Torchvision ResNet-18 is the classifier. The repository also includes a patch-based, tiled-inference pipeline with a bootstrap-CI evaluation harness.

> **Scope note.** MIDV-500/2020 contain only genuine (mock-identity) documents. Every "tampered" sample here is generated by this project's own forgery code, so reported numbers measure detection of *these synthetic edits*, not real-world fraud.

## Highlights

- End-to-end pipeline: data preparation, forgery synthesis, training, evaluation, inference.
- Five forgery types: text replacement, inpainting-based erasure, copy-move, cross-document splicing, local blur.
- Leakage-safe protocol: splits by document group, genuine/tampered pairs kept together, identical resizing and JPEG encoding for both classes.
- Threshold chosen on validation only; per-forgery-type breakdown reported.
- Optional Tesseract OCR field extraction with a date-validity sanity check (heuristic, not evaluated).

## Dataset and licence

MIDV-2020 and/or MIDV-500 (mock identity documents, no real personal data). Check each dataset's licence and terms on its official page before use. The data is not included in this repository.

## Method

```
raw MIDV images
  -> text-box detection (OpenCV morphology, optional Tesseract)
  -> forgery synthesis (5 operations)
  -> ResNet-18 (ImageNet-pretrained, 1-logit head, BCE loss)
  -> threshold tuned on validation (Youden's J)
  -> test metrics + per-forgery-type detection rate
```

The repository contains two input configurations:

- **Whole-image baseline** (480x320, one forward pass). All results below come from this configuration.
- **Patch-based pipeline** (768x512 storage, 256x256 forgery-centred training crops, 12-tile sliding-window inference, bootstrap CIs, EER, TPR at fixed FPR, localisation hit-rate). Implemented in `src/`; **not yet evaluated** at the time of writing.

## How to run

```bash
pip install -r requirements.txt

# smoke test, no dataset needed
python scripts/make_demo_data.py --n 120
python run_all.py --raw_dir data/raw/demo --max_images 120 --epochs 2

# real run
python run_all.py --raw_dir data/raw --include scan_upright --max_images 6000 --epochs 20

# inference with heat-map
python -m src.infer --image some_id.jpg --heatmap --ocr
```

## Results (whole-image baseline, 8 epochs, test n = 3,578)

Training time: about 41 minutes.

| Threshold | Accuracy | Precision | Recall | F1 | AUC | Specificity |
|---|---|---|---|---|---|---|
| 0.50 | 0.583 | 0.729 | 0.266 | 0.389 | 0.618 | 0.901 |
| 0.464 (validation-tuned) | 0.582 | 0.639 | 0.377 | 0.474 | 0.618 | 0.787 |

| Forgery type | Detection rate (validation-tuned threshold) |
|---|---|
| splice | 0.804 |
| copy_move | 0.369 |
| erase | 0.251 |
| local_blur | 0.238 |
| text_replace | 0.221 |

Genuine documents accepted: 78.7%.

## Analysis

- **Under-trained.** Training loss stayed near ln 2 (0.693, chance level) for epochs 1-6 and only began falling in epochs 7-8, while validation AUC was still rising (0.612 at epoch 8). Eight epochs were not enough for convergence.
- **Only coarse forgeries are caught.** Splicing introduces large foreign content and is detected 80% of the time. Local edits (text replacement, erasure, blur) are mostly missed (22-25%).
- **Likely cause: resolution loss.** Downscaling whole documents to 480x320 suppresses the high-frequency traces left by small edits. This is consistent with the per-type results but has not been isolated by a controlled ablation. The patch-based pipeline in this repo was built to test it.
- **Practical reading.** The baseline is conservative (90% specificity, 27% recall at 0.5) and is not suitable for any real verification use.

## Limitations

- Synthetic forgeries generated by the same code that defines the labels; the classifier may learn generator artefacts. Real-world performance is unknown.
- Narrow domain: MIDV mock documents with limited templates and backgrounds.
- Single run, single seed, no confidence intervals for the baseline numbers above.
- The OCR date check is heuristic and unevaluated.
- Not compared against published methods or commercial systems.
